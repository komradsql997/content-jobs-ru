# Главред нашёл вакансии — вакансии для специалистов по контенту

Бесплатный MVP агрегатора **российских вакансий для работы в РФ**. Редакторы, UX-писатели, копирайтеры, технические писатели, главреды, контент-маркетологи.

**Статус:** публичный MVP. Первый успешный сбор вакансии с сайта Яндекса подтверждён 24 ноября 2026 года. Остальные источники ещё не подтверждены. Источники из `sources.json` пока кандидаты на интеграцию, а не гарантированно работающие парсеры. Реальная загрузка должна быть подтверждена отчётом GitHub Actions. Не подменять нулевые результаты фиктивными вакансиями.

## Как устроено
- `site/` — статический сайт без сервера и платных сервисов, получает `jobs.json`.
- `scripts/collect.py` — проверяет российские карьерные площадки, извлекает карточки, фильтрует по профессиям и географии, удаляет повторы и выставляет балл полноты описания.
- `sources.json` — список сайтов. Внесение нового источника не требует изменения кода.
- `.github/workflows/update.yml` — запуск в 11:00, 16:00 и 21:00 МСК, сохранение отчёта, обновление сайта и попытка деплоя GitHub Pages.
- `reports/source_diagnostics.json` — отчёт проверки источников; в Actions он также прикрепляется как артефакт.

Telegram-каналы пока НЕ подключены. Для законного сбора потребуются согласование с владельцами и подключение бота к каналам. Не используем международные агрегаторы и hh API.

## Бесплатное размещение
1. GitHub → репозиторий → **Settings → Pages → Build and deployment → Source: GitHub Actions**.
2. Actions → **Обновить вакансии и сайт** → **Run workflow**. При первом запуске потребуется разрешить Actions в репозитории.
3. После успешного запуска вкладка **Settings → Pages** покажет адрес сайта. Обычно это `https://komradsql997.github.io/content-jobs-ru/`.
4. Отчёт смотри в Actions → последний запуск → **source-diagnostics**. Пока источники не дали вакансии, сайт покажет честное пустое состояние.

## Локальная проверка (необязательно)
```bash
pip install -r requirements.txt
python -m unittest discover -s tests -v
python scripts/collect.py
python -m http.server 8000 --directory site
```

Сборщик не обходит блокировки, не отключает проверку сертификатов, не использует платные API. Публикуется только короткая выдержка и ссылка на первоисточник. Права и условия каждого источника нужно проверять до постоянной публичной эксплуатации. Даты у объявлений без исходной даты — время обнаружения, а не публикации.

## Зарплатные ориентиры
Если работодатель не указал зарплату, сервис показывает ориентир **только при наличии не менее трёх вакансий с реальными зарплатами** в той же специализации и на том же уровне. Пока выборки нет, ориентир скрыт — не публикуем произвольные цифры как рыночные данные.

## Где размещён сайт
https://komradsql997.github.io/content-jobs-ru/ — GitHub Pages подходит для публичного бесплатного прототипа. Для коммерческого SaaS или онлайн-бизнеса условия GitHub Pages не предназначены: потребуется другой хостинг. Собственный домен можно добавить отдельно без смены движка.

## Известные ограничения
- Подтверждён пока один работающий карьерный источник — Яндекс; остальных кандидатов нельзя считать подключёнными, пока они не возвращают реальные вакансии.
- Telegram-каналы ожидают лицензионный API-ключ стороннего провайдера и подтверждение прав на использование данных.
- Поля вакансии извлекаются из текста автоматически и могут быть неполными. Архивные объявления должны исключаться на этапе сбора.

## Telegram вакансии без администраторского доступа

**Предыдущую интеграцию Bot API не используем.** Требовать добавления нашего бота в администраторы чужих каналов не нужно.

Скрипт `scripts/tgstat_collect.py` поддерживает два режима внешнего API TGStat:

- `search`: TGStat Search API, поиск публичных публикаций по тематическим запросам (`posts/search`), настраиваемый лимит 5 запросов за один запуск (примерно 450 запросов/30 дней при 3 запусках/сутки). Возвращает поиск по базе, **не гарантирует** покрытие всех 45 каналов.
- `channels`: TGStat Stat API, получение последних публикаций каждого канала (`channels/posts`), 5 каналов за запуск с ротацией; для покрытия 45 каналов за 3 запуска в день потребуется минимум 15 запросов за запуск. Для чужих каналов нужен платный тариф. Результаты `channel_usernames` из `tgstat_config.json` обрабатываются только при наличии доступа к провайдеру.

Нет пользовательской сессии Telegram, парсинга t.me/s и запросов администраторских прав.

**До активации** нужны два независимых условия: действующий тариф и секрет `TGSTAT_API_TOKEN` в GitHub Actions, а также подтверждённые права на использование полученного контента на публичном агрегаторе (`TGSTAT_RIGHTS_CONFIRMED=true` в Actions Variables). Наличие API-ключа не заменяет разрешения на публичную публикацию и не отменяет правил Telegram и TGStat.

Без ключа или подтверждения прав ничего не скачивается и никаких запросов или расходов на TGStat нет. Хостинг и GitHub Actions остаются бесплатными. Вакансии из TGStat хранятся в `data/tgstat_jobs.json` до 14 дней и объединяются с карьерными вакансиями; на сайте показываем только краткие сведения и ссылку на оригинал.

Техническая документация: https://api.tgstat.ru/docs/ru/start/intro.html, https://api.tgstat.ru/docs/ru/posts/search.html, https://api.tgstat.ru/docs/ru/channels/posts.html
